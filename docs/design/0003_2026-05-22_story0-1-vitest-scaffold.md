## Decisions and rationale

1. **Vitest version `^2.1.9`** rather than `^2.1.0` from the story text. The story uses "e.g. `^2.1.0`" indicating a floor example. `^2.1.9` is the latest 2.1.x at install time and within the same caret range. Same major.minor compatibility guarantees.

2. **Imports sorted alphabetically** in placeholder (`describe, expect, it`). The repo's `sort-imports` rule (eslint.config.mjs:42-51) with `ignoreMemberSort: false` enforces alphabetical member order. The exact wording in story line 40 (`describe, it, expect`) would fail lint; the implemented form is the only one satisfying both the placeholder requirement and the lint rules.

3. **Format script extended too** (`prettier --write 'src/**/*.ts' 'test/**/*.ts'`). Not strictly listed in story acceptance criteria but is a logical companion to the lint glob extension — without it, `npm run format` would skip test files and developers would get diffs from formatting drift. Low-risk symmetric extension.

4. **No vitest.config.ts** created. Story §"Technical notes" line 56 says defaults work for pure-helper tests. Adding config now would be premature.

5. **No CI test job** added. Story §"Out of scope" line 50 defers this to a follow-up.
