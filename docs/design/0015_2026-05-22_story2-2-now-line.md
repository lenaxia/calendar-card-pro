## Summary

Implemented the now-line for the time-grid view: a 2px horizontal indicator
inside today's day column that tracks the current time. Position updates run
on a 60-second `setInterval` and mutate `style.top` directly — no Lit
re-render. The interval is started/stopped in `connectedCallback` /
`disconnectedCallback` and re-evaluated whenever `view` or
`time_grid_show_now_line` changes.

Story 2-3 will add the midnight-detection branch at the top of
`_updateNowLinePosition`; this story leaves `_lastRenderDay` initialized
but unused.

## Decisions

1. **Where the `_lastRenderDay` and `_nowLineIntervalId` fields are declared** —
   placed adjacent to the existing `_resizeObserver` / `_resizeRafId` fields
   for readability (both are time-grid lifecycle state).
2. **Where `_stopNowLine` is called in `disconnectedCallback`** — placed after
   the existing ResizeObserver cleanup, so the order is observer → interval.
   Cleanup order doesn't matter functionally (both are independent), but
   keeping observer first matches the order they appear in `connectedCallback`.
3. **`updated()` extension** — handles both view-change and
   `time_grid_show_now_line`-toggle in one branch by recomputing the desired
   state and idempotently calling `_stopNowLine()` then conditionally
   `_startNowLine()`. Story 2-2 spec showed two separate `if`/`else if`
   branches; collapsing them is equivalent because `_startNowLine` and
   `_stopNowLine` are both idempotent (`_startNowLine` early-returns when
   already running).
4. **`_lastRenderDay` initialization runs at construction time, not first
   tick** — matches the spec's intent (avoid a spurious first-tick
   `requestUpdate` once story 2-3 lands). Implemented as an IIFE in the field
   initializer.

## Post-implementation fix (validation pass 1)

Validation pass 1 noted a subtle fragility: `_startNowLine` is called from
`connectedCallback`, which runs **before** the first render commits. The
synchronous `_updateNowLinePosition()` call inside `_startNowLine` finds
`renderRoot.querySelector(...)` returns null (DOM not yet rendered) and
early-returns. The line then would not appear until either (a) the first
60s tick fires, or (b) the `updated()` view-change branch re-invokes
`_startNowLine` after the DOM commits. Path (b) typically saves us because
DEFAULT_CONFIG.view='list' triggers a view change on first render — but
this is implicit and fragile to future DEFAULT_CONFIG changes or pathological
`setConfig` paths where prevConfig.view already equals current.

Fix applied: added a minimal `firstUpdated()` hook that calls
`_updateNowLinePosition()` once when `view === 'time-grid'` and
`time_grid_show_now_line` are true. This guarantees correct positioning on
the very first render regardless of the `updated()` branch path. Lint clean,
88 tests still pass, build succeeds.
